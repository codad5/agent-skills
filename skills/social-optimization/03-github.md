# GitHub optimization

## Do first
1. Bio (top of profile, and the `<username>/<username>` profile README repo if one exists) — same self-label discipline as everywhere else. Check it against the person's stated preference explicitly; GitHub bios are frequently the stalest surface because people set them once early on and never revisit.
2. Pinned repos — should reflect current focus (systems/backend/language of choice), not just whatever has the most stars. A repo with few stars but current, relevant work beats an old high-star repo in an abandoned direction.

## Watch for
- **Third-party embedded widgets in the profile README** (e.g. a "GitRoll" or similar score-card badge) can display a stale or generic title/label pulled from an old bio or its own heuristic — these read as part of the person's own profile to a visitor even though the person doesn't control the wording directly. Flag it; fixing it usually means updating the underlying service's own read of the profile, or removing the embed.
- **Org membership and contribution graph** are useful signals to mention in cross-referencing (Phase 0) — they show real, dated activity that's harder to fake/stale than a bio line.
- Check for a linked personal site / portfolio URL in the profile — should point to the current, live one.

## What NOT to do
- Don't touch pinned-repo order without asking — some people intentionally lead with a specific flagship project for reasons research may not surface (e.g. it's what a specific audience they're targeting cares about).
- Don't remove old repos wholesale; GitHub repos are commit history and portfolio evidence at once. Only recommend hiding/unpinning, not deleting, unless the person explicitly wants a repo gone.
