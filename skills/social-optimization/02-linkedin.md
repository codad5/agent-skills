# LinkedIn optimization

## Do first (highest leverage, lowest risk)
1. Headline — tight, keyword-rich, matches the person's stated self-label exactly. Formula: `[Role] — [Specialty] | [Core skills] | [Notable affiliation]`.
2. About section — hook line, 1-2 narrative paragraphs, bulleted highlights, tech stack line, CTA. Every stale number gets refreshed here first since it's the most-read section.
3. Experience — every entry gets a real description ending in a `Technologies:` line. Never leave one blank; LinkedIn indexes this text for recruiter search.

## Then, in this order
4. Add any missing current roles (e.g. a founder's own studio/company) as real Experience entries, not just a mention in About — Experience is what search indexes and what a scanning reader checks for a timeline. Link it to the real LinkedIn company page if one exists (an autocomplete usually offers it while typing the organization field).
5. Projects — same bullet + `Technologies:` treatment. Attach the project's real skills (LinkedIn's "Add skill" inside a project form) and a link (via "Add media" → "Add a link", not the file-upload option) to a live URL for it. If the project was built under a company/studio, use the "Associated with" dropdown inside the project edit form to link it to that Experience entry.
6. Skills — expand toward 40-50 real skills matching actual job-posting phrasing for the person's target roles, not just what's already used elsewhere. Pin the top 3.
7. Remove/clean: outdated Featured posts that don't reflect current focus, low-value certifications (a "Learning X" beginner course sitting next to a "6 years experience" claim undercuts it), low-tier honors/badges, and old/junior projects with typos or scope far below current level.
8. Settings check: Settings → Visibility → confirm public profile discovery is on, full last name is shown, connection/follow visibility is open. Don't assume these are already right.
9. Banner — see [07-banner-generation.md](07-banner-generation.md).

## LinkedIn-specific gotchas (all confirmed in real runs, not theoretical)

- **Detail sub-pages sometimes render blank on first load** (`/details/certifications/`, `/details/skills/` list view, `/details/featured/` in some states) even though the data exists — confirmed via the public-profile-preview page and via indirect signals (a new tab category appearing). Try: reload once, scroll the actual scroll container (it's `document.querySelector('main')`, not `window` — LinkedIn's layout puts the real scrollbar on `<main>`), and wait several seconds before concluding it's broken. If still blank, this is a genuine platform-side rendering issue in an automated session — note it and move on rather than burning many retries.
- **Editing Experience/Projects works via direct URLs once you have the position/project ID**: `/details/experience/edit/forms/<id>/` and `/details/projects/edit/forms/<id>/` — get the IDs by scrolling the `/details/experience/` or `/details/projects/` list page and reading the `aria-label` + `href` off each item's edit link (`"Edit <title> at <company>"` / `"Edit project <name>"`). New entries: `/edit/forms/project/new/` for a project, position `new` forms are reached via the `+` on the details page (the guessed `/details/projects/edit/forms/new/` URL 500s — don't use it).
- **Deleting an entry**: click "Delete project" / equivalent, which opens a confirmation modal with a *second* "Delete" button — you need both clicks. Same two-step pattern for Experience.
- **Saving a new "current" position auto-overwrites the profile headline** to `<title> at <company>`, silently discarding a custom headline. Always re-check and re-fix the headline immediately after adding/editing any position marked "currently working here."
- **A checkbox-driven form (e.g. the Services page's service-type checkboxes) can visually toggle and still fail to persist** — this is a React controlled-component issue: a scripted click or a native-setter + dispatched event can change what's on screen without updating LinkedIn's internal state, so Save submits nothing (verify via network requests: zero requests firing on Save is the tell). Diagnosing this thoroughly (native click → native property setter + events → reaching the framework's actual onChange handler) is worth doing once to be sure it's a real platform limitation, but don't loop on it forever — if all three fail and zero network calls fire on Save, this is genuinely a manual-only fix; say so plainly and move on.
- **A "site/link" attachment (e.g. a project's external link) needs "Add media" → "Add a link"**, not a plain URL text field on the main form — the option only appears after clicking "Add media" and choosing from a small menu (link / image / document). Preview generation is flaky — retry once if you see "We couldn't generate a preview for this link"; it usually works the second time. If the auto-fetched title exceeds LinkedIn's 200-character limit, shorten it manually before the inner Save enables.
- **Reorder features are unreliable**: the dedicated Featured-reorder page returned a real HTTP 500 from LinkedIn's own servers in one run. Don't assume manual drag-reordering works via automation — if the person wants a specific display order for Experience/Projects and no reliable reorder control exists, tell them the recommended logical order and let them drag it themselves if their own (non-automated) browser session supports it.
- **A duplicate can appear if a delete and a re-create race each other** (e.g. the person deletes an entry live while you're mid-edit-flow on a stale reference to it) — always re-list the section after any batch of adds/deletes to confirm the final count and catch duplicates before declaring done.
